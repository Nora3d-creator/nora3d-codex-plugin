# Nora3D 0.2.0-beta.24: desktop acceptance

Confirm beta.24 in plugin Information and start a new task after installing the
package. Keep only one Online Beta plugin enabled. Use disposable test documents.
The new Web assistant page has no MCP button; do not enable a legacy page mode.

1. **First connection:** complete the host's normal Nora3D installation
   authorization. Sign in on the intended Nora3D page and open a part document
   with its existing Assistant panel. Confirm the plugin reads the exact
   project/document and live session through guarded context, without a button,
   hidden code lookup, copied request or account-switch loop.
2. **Historical sessions:** leave offline records for this document. Confirm they
   are ignored. With two live sessions and no retained binding, require explicit
   disambiguation rather than choosing the newest. A different document must
   never be substituted, even when it is the only available workspace.
3. **Model:** request an 80 x 50 x 6 mm plate with a centered 10 mm through-hole.
   Check native dimensions, one solid, through-depth and saved/displayed receipts.
4. **Continue:** change thickness to 8 mm; preserve the hole and unrelated geometry.
   Once idle and saved, reopen the test document. Rediscover and check the new
   session before further modeling. Confirm persisted geometry and feature history.
5. **Images and language:** an explicit drawing-modeling request proceeds from
   interpretation to modeling, checks and save without another "go on". Replies
   follow the user's language. "Analyze only" must not change geometry. An
   ambiguous attachment outside a modeling request must not authorize edits.
6. **Concurrent Web work:** while the Web assistant is modeling, desktop writes
   must honor assistant_busy. Do not cancel its turn or clear its lease. Preserve
   both Web and manual drafts, unsent messages and uploaded references.
7. **Connection recovery:** temporarily disconnect a saved idle test page. Resume
   from fresh context and actual completed receipts, with no duplicate operations.
   A tab-opening timeout must first inspect the existing tab; no duplicate page,
   speculative More click, hidden-code wait or automatic reload is allowed.
8. **Authorization boundary:** an accessible delegated document works without a
   new consent. A different-account document without a valid delegation is not
   made accessible by a URL. Report the actual access gap without guessing from
   an empty list, reading credentials, restoring an MCP button or changing Web.
9. **Failures and cancellation:** inspect unknown writes without replay or automatic
   acceptance. Preserve completed geometry after cancellation. Do not promise the
   Web host's automatic reload/resume behavior in a desktop task.
10. **Optional mesh tools:** needs_codex is analysis requiring continued modeling,
    not a saved solid. Recheck source/session validity before using evidence.

Record version, step, expected/actual result and non-secret error codes. Test Git
marketplace Upgrade only after publication; a local ZIP cannot prove Git updates.
These scenarios are acceptance requirements, not claims that every case passed.
